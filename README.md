## Architecture Overview

RhizoSense enforces a strict separation of concerns: presentation is decoupled from agricultural domain intelligence.

```text
┌──────────────────────────────────────┐
│  Agricultural Simulator (Python CLI) │
│  - normal, drought, pest, heat, flood│
└──────────────────┬───────────────────┘
                   │ HTTP POST /api/simulator/telemetry
                   ▼
┌──────────────────────────────────────┐
│   FastAPI Backend & Rules Engine     │
│   - Domain rules & threshold engine  │
│   - Edge AI inference assessment     │
│   - Localized status calculation     │
│   - WebSocket event broadcaster      │
└──────────┬───────────────────┬───────┘
           │ HTTP (REST)       │ WebSocket (/ws)
           ▼                   ▼
┌──────────────────────────────────────┐
│   React + TypeScript Frontend        │
│   - Overview, Fields, Field Detail   │
│   - Interactive Recharts analytics   │
│   - 3-toast queue & Notification hub │
└──────────────────────────────────────┘
```

* **No Agricultural Logic in Frontend**: All threshold evaluations (`soilMoisture < 20`, heat stress calculations, risk scoring, recommendations) are computed by the backend rules engine (`backend/app/services/rules_engine.py`).
* **Zero Frontend Randomness**: No `Math.random()` or fake random data for agricultural states. All UI states originate deterministically from backend state and WebSocket telemetry events.
* **Independent Simulator**: Telemetry is generated by an external standalone CLI tool, simulating realistic edge sensors.

## Local Development Setup

### Prerequisites
* **Python 3.10+** (Tested on Python 3.11, 3.12, 3.14)
* **Node.js 18+** and **npm**

---

### Step 1: Start the Backend Service

```bash
# Install Python dependencies
pip install -r requirements.txt

# Start the FastAPI server on port 8000
python -m uvicorn backend.app.main:app --host 127.0.0.1 --port 8000 --ws websockets --reload
```

* **Interactive API Docs (Swagger UI)**: [http://127.0.0.1:8000/docs](http://127.0.0.1:8000/docs)
* **Health Check**: [http://127.0.0.1:8000/api/health](http://127.0.0.1:8000/api/health)

---

### Step 2: Start the Frontend Application

In a separate terminal window:

```bash
cd frontend

# Install Node dependencies
npm install

# Start Vite development server
npm run dev
```

* **Dashboard URL**: [http://localhost:5173](http://localhost:5173)

---

### Step 3: Run the Agricultural Simulator

In a third terminal window, launch the interactive scenario simulator:

```bash
# Run primary demo: Drought progression on Field C
python simulator.py --scenario drought

# Other supported scenarios:
python simulator.py --scenario pest      # Pest outbreak with acoustic/vision edge detection
python simulator.py --scenario heat      # Ambient temperature surge and heat stress
python simulator.py --scenario flood     # Waterlogging and root saturation
python simulator.py --scenario normal    # Nominal diurnal baseline variation

# Useful flags:
#   --interval 0.5   (update every 0.5s)
#   --duration 25    (stop after 25 ticks)
#   --dry-run        (test locally without sending network requests)
```

---

### Step 4: Run Tests

```bash
# Run backend pytest suite
python -m pytest backend/tests/test_backend.py -v

# Run frontend type-check and production build
cd frontend
npm run build
```

## Cloud Deployment Guide

RhizoSense is pre-configured for instant zero-friction deployment:
* **Backend**: Deployed as a Python Web Service on [Render](https://render.com) (with WebSocket support).
* **Frontend**: Deployed as a single-page Vite application on [Vercel](https://vercel.com).

---

### Part 1: Deploy Backend to Render

You can deploy the backend on Render either using the included Blueprint (`render.yaml`) or manually via the Render dashboard.

#### Method A: Using Render Blueprint (Recommended)
1. Push your repository to your GitHub account.
2. Log in to [Render](https://dashboard.render.com).
3. Click **New +** → **Blueprint**.
4. Select your `RhizoSense` repository.
5. Render will automatically read `render.yaml` and configure:
   * **Build Command**: `pip install -r requirements.txt`
   * **Start Command**: `uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT --ws websockets`
   * **Plan**: Free
6. Click **Apply**. Once deployed, copy your backend URL (e.g. `https://rhizosense-backend.onrender.com`).

#### Method B: Manual Web Service Setup
1. On the Render dashboard, click **New +** → **Web Service**.
2. Connect your GitHub repository.
3. Configure the settings:
   * **Name**: `rhizosense-backend`
   * **Language**: `Python 3`
   * **Branch**: `main` (or your default branch)
   * **Region**: Choose the closest region to you
   * **Root Directory**: Leave blank (repository root)
   * **Build Command**: `pip install -r requirements.txt`
   * **Start Command**: `uvicorn backend.app.main:app --host 0.0.0.0 --port $PORT --ws websockets`
   * **Instance Type**: `Free`
4. Expand **Advanced** → **Add Environment Variable**:
   * `PYTHON_VERSION` = `3.11.9`
   * `CORS_ORIGINS` = `*`
5. Click **Create Web Service**.
6. When the build finishes, copy your live backend URL (e.g., `https://rhizosense-backend.onrender.com`).

---

### Part 2: Deploy Frontend to Vercel

1. Log in to [Vercel](https://vercel.com).
2. Click **Add New...** → **Project**.
3. Import your GitHub repository.
4. In the configuration screen:
   * **Project Name**: `rhizosense` (or your preferred name)
   * **Framework Preset**: `Vite`
   * **Root Directory**: Click **Edit** and select `frontend` *(Important!)*
   * **Build Command**: `npm run build` (default)
   * **Output Directory**: `dist` (default)
5. Expand **Environment Variables** and add:
   * **Name**: `VITE_API_URL`
   * **Value**: `https://your-render-service.onrender.com/api`  
     *(Replace `your-render-service` with your actual Render URL from Part 1)*
   
   *(Optional)*:
   * **Name**: `VITE_WS_URL`
   * **Value**: `wss://your-render-service.onrender.com/ws`  
     *(Note: If omitted, RhizoSense will automatically derive the `wss://` URL from `VITE_API_URL`)*
6. Click **Deploy**.
7. Vercel will build the frontend. Once complete, your dashboard will be live at `https://your-project.vercel.app`.

> **Note on Client-Side Routing**: The included `frontend/vercel.json` provides an SPA rewrite rule (`/(.*) -> /index.html`), ensuring direct URLs like `/fields/field-c` and `/analytics` do not return 404 errors on page refresh.

---

### Part 3: Run the Simulator Against Cloud Backend

Once deployed to Render, you can drive live agricultural simulations on your cloud dashboard from any local terminal:

```bash
python simulator.py --scenario drought --backend-url https://your-render-service.onrender.com
```

Watch the cloud dashboard on Vercel update in real time:
1. Soil moisture drops in Field C.
2. Status transitions from **NORMAL** → **WARNING** → **CRITICAL**.
3. Toast notifications appear in the bottom-right corner.
4. The Attention Required panel highlights the issue.
5. Click into Field C to view edge AI inference and recommendations.

## Environment Variables Reference

### Frontend (`frontend/.env`)
| Variable | Required | Default | Description |
| :--- | :---: | :--- | :--- |
| `VITE_API_URL` | No | `http://127.0.0.1:8000/api` | Base URL of the FastAPI REST API. |
| `VITE_WS_URL` | No | Auto-derived from `VITE_API_URL` | WebSocket endpoint for live updates. |

### Backend (`backend/.env`)
| Variable | Required | Default | Description |
| :--- | :---: | :--- | :--- |
| `PORT` | No | `8000` | Port for the Uvicorn server (automatically set by Render). |
| `HOST` | No | `0.0.0.0` | Network interface to bind. |
| `CORS_ORIGINS` | No | `*` | Allowed CORS origins, comma-separated (e.g., `https://rhizosense.vercel.app`). |

## Verification & Quality Standards

* **No Agricultural Logic in React**: All agronomic threshold calculations, water stress models, pest risk scores, and recommendations reside exclusively in `backend/app/services/rules_engine.py`.
* **Zero Randomness in UI**: `Math.random()` is not used for agricultural state calculation.
* **Light Theme Conformance**: Strictly light palette (`#F6F7F5` page background, `#FFFFFF` surfaces, localized status colors).
* **Accessible UI**: Uses semantic HTML, visible focus states, ARIA labels on icon buttons, and `lucide-react` icons (no emoji icons for domain status).
* **Toast Queue System**: Maximum 3 concurrent toasts, ~2.5s duration, graceful fade-out, with permanent logging in the Notification Center.
